# Discord TTS-бот (Azure Speech)

Бот заходит в голосовой канал и озвучивает текстовые сообщения определённых
игроков через **Azure Cognitive Services Speech**. Запасной провайдер —
**SaluteSpeech** (Сбер), переключается одной строкой в `.env`.

## Как работает

1. Игрок из списка `allowed_users.json` пишет сообщение в **чат голосового
   канала** (встроенный текстовый чат voice-канала).
2. Если канал входит в список отслеживаемых (`TRACKED_CHANNEL_IDS`), бот
   подключается к этому голосовому каналу (в авто-режиме).
3. Текст превращается в речь (Azure Speech) и проигрывается.
4. Сообщения проигрываются по очереди, не накладываясь.

## Провайдер синтеза речи

Задаётся в `.env` переменной `TTS_PROVIDER`:

| Значение | Провайдер | Настройки |
|---|---|---|
| `azure` (по умолчанию) | Azure Cognitive Services Speech | `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`, `AZURE_VOICE` |
| `salute` | SaluteSpeech (Сбер) | `SALUTE_AUTH_KEY`, `SALUTE_SCOPE`, `SALUTE_VOICE` |

Оба провайдера дают боту одинаковый интерфейс (см. `tts_base.py`), поэтому
переключение не требует правок кода — только смены `TTS_PROVIDER` и перезапуска.

## Режимы подключения и команды

Режим задаётся в `.env` (`CONNECTION_MODE`) и переключается на лету командой.

- **auto** — бот сам заходит в голосовой канал, когда игрок из списка пишет
  в его чат, и сам выходит после `IDLE_TIMEOUT_MINUTES` минут тишины.
- **manual** — бот заходит/выходит только по командам; сообщения озвучиваются,
  только пока бот уже находится в этом канале.

Команды (доступны игрокам из списка и администраторам сервера, пишутся в чат
голосового канала):

| Команда | Действие |
|---|---|
| `!join` | подключить бота к текущему голосовому каналу |
| `!leave` / `!stop` | отключить бота |
| `!mode` | показать текущий режим |
| `!mode auto` / `!mode manual` | переключить режим |
| `!balance` | показать расход символов (и остаток пакетов у Сбера) по всем ключам |
| `!speak <текст>` | принудительно озвучить текст (только заданные роли) |

> `!speak` доступен администраторам и обладателям ролей из `SPEAK_ROLE_IDS` /
> `SPEAK_ROLE_NAMES`. Бот сам подключится к каналу и озвучит текст, независимо
> от режима и от того, есть ли автор в `allowed_users.json`.

## Учёт расхода символов (`!balance`)

У Azure **нет API остатка средств**, поэтому расход бот считает сам: после
каждой удачной озвучки прибавляет длину текста к счётчику активного ключа.
Счётчики лежат в `USAGE_FILE` (по умолчанию `usage.json`) и обнуляются при
смене календарного месяца — так же, как обновляется бесплатная квота.

`MONTHLY_QUOTA_CHARS` задаёт квоту на ключ для процентов в `!balance`
(бесплатный тариф **F0** — 500 000 символов в месяц на ресурс; поставьте `0`,
если тариф платный). Пустой `USAGE_FILE` отключает учёт.

> Счёт локальный и приблизительный: он не видит запросы, сделанные тем же
> ключом из других приложений, и обнуляется, если удалить файл. Точные цифры —
> в портале Azure (метрики ресурса / Cost Management).

Для `salute` счётчик тоже работает, а вдобавок `!balance` показывает остаток
пакетов из API Сбера (доступен не на всех тарифах: на бесплатном персональном
`SALUTE_SPEECH_PERS` метод может вернуть ошибку — это нормально).

## Несколько ключей (авто-переключение)

Можно задать 2–10 ключей: когда у активного кончается квота (или он
блокируется/упирается в лимит), бот автоматически переключается на следующий
рабочий ключ.

1. Скопируйте шаблон: `cp azure_keys.example.json azure_keys.json`.
2. Впишите свои ключи. Каждый ключ — отдельный ресурс Speech в портале Azure;
   `region` и `voice` можно не указывать, тогда возьмутся значения из `.env`.
3. Путь к файлу — в `.env` (`AZURE_KEYS_FILE`, по умолчанию `azure_keys.json`).

Если файл существует, он имеет приоритет над одиночным `AZURE_SPEECH_KEY`.
Файл `azure_keys.json` добавлен в `.gitignore` — он содержит секреты.

> Переключение срабатывает, когда SDK отменяет синтез с `AuthenticationFailure`
> (401), `Forbidden` (403 — квота исчерпана) или `TooManyRequests` (429).
> Прочие ошибки (сеть, 5xx) ключ не «сжигают». При перезапуске бота пометки
> «исчерпан» сбрасываются.

Для SaluteSpeech всё то же самое через `salute_keys.example.json` →
`salute_keys.json` и `SALUTE_KEYS_FILE`.

### Что НЕ озвучивается

- Сообщения, начинающиеся с `SKIP_PREFIX` (по умолчанию `!`) — например,
  `!это в чат, но без голоса`. Сообщение остаётся в чате, но не читается.
- Ссылки `http://…` / `https://…` вырезаются из текста перед озвучкой.
  Если кроме ссылки в сообщении ничего не было — оно не озвучивается.
- Сообщения вне чата голосового канала и из каналов не из списка.

> Префикс команд настраивается (`COMMAND_PREFIX`). Поскольку он по умолчанию
> совпадает со `SKIP_PREFIX` (`!`), команды и так не озвучиваются.

## Требования

- Python 3.10+
- **FFmpeg** в `PATH` (нужен discord.py для воспроизведения).
  Windows: `winget install Gyan.FFmpeg` или скачать с https://ffmpeg.org
- Бот в Discord Developer Portal с включённым **Message Content Intent**
  (Bot → Privileged Gateway Intents).
- Ресурс **Speech** в портале Azure (подойдёт бесплатный тариф F0).
- На Linux пакет `azure-cognitiveservices-speech` тянет нативные библиотеки —
  нужны `libssl` и `libasound2` (см. [DEPLOY_UBUNTU.md](DEPLOY_UBUNTU.md)).

## Права и интенты бота в Discord

### Privileged Gateway Intents (Developer Portal → Bot)

- **Message Content Intent** — **обязательно**. Без него бот не видит текст
  сообщений и не сможет ничего озвучить.
- Server Members Intent и Presence Intent **не нужны** — не включайте.

### Права бота на сервере / канале

Боту нужны перечисленные ниже права. Их можно выдать роли бота
(Настройки сервера → Роли) либо на конкретном голосовом канале
(ПКМ по каналу → Изменить канал → Права доступа).

| Право | Англ. | Зачем |
|---|---|---|
| Просматривать каналы | View Channels | видеть голосовой канал и его чат |
| Читать историю сообщений | Read Message History | читать сообщения в чате канала |
| Отправлять сообщения | Send Messages | ответы на команды (`!join`, `!balance`, …) |
| Подключаться | Connect | заходить в голосовой канал |
| Говорить | Speak | воспроизводить озвучку |

> ⚠️ Права на **уровне канала** перекрывают права роли. Даже если у роли есть
> Connect, отдельный запрет (красный крестик ✗) на канале его заблокирует —
> проверяйте именно настройки нужного голосового канала.

При старте бот сам пишет в лог по каждому отслеживаемому каналу
`права OK` или `НЕТ ПРАВ: …` — удобно проверить, чего не хватает.

### Пригласить бота сразу с правами (рекомендуется)

Developer Portal → **OAuth2 → URL Generator**:

1. **Scopes:** `bot`.
2. **Bot Permissions:** View Channels, Read Message History, Send Messages,
   Connect, Speak.
3. Откройте полученную ссылку и выберите сервер.

## Установка

```powershell
cd discord-tts-bot
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Настройка

1. Скопируйте `.env.example` в `.env` и заполните:
   - `DISCORD_TOKEN` — токен бота;
   - `AZURE_SPEECH_KEY` и `AZURE_SPEECH_REGION` — портал Azure → ресурс Speech →
     «Keys and Endpoint» → KEY 1 и Location/Region (например `westeurope`);
   - при необходимости `AZURE_VOICE`, `AZURE_OUTPUT_FORMAT`, `MONTHLY_QUOTA_CHARS`.
2. Создайте список игроков из шаблона и отредактируйте его — впишите
   Discord ID (надёжнее) и/или ники:

   ```powershell
   copy allowed_users.example.json allowed_users.json
   ```

   Сам `allowed_users.json` в `.gitignore`: в нём личные Discord ID,
   и в репозиторий они попадать не должны.

> Чтобы скопировать ID пользователя: в Discord включите
> Настройки → Расширенные → Режим разработчика, затем ПКМ по пользователю → «Копировать ID».

## Настраиваемые голоса

Голос Azure задаётся в `.env` параметром `AZURE_VOICE`. Русские нейроголоса:
`ru-RU-SvetlanaNeural`, `ru-RU-DmitryNeural`, `ru-RU-DariyaNeural`. Полный
список — в [документации Azure](https://learn.microsoft.com/azure/ai-services/speech-service/language-support?tabs=tts).

Дополнительно можно подкрутить SSML:

- `AZURE_VOICE_RATE` — темп (`-10%`, `+20%`, `slow`);
- `AZURE_VOICE_PITCH` — высота (`+5%`, `high`);
- `AZURE_VOICE_STYLE` — стиль (`cheerful`, `sad`, …). Поддерживается не всеми
  голосами; у русских нейроголосов стилей нет — оставьте пустым.

`AZURE_OUTPUT_FORMAT` — имя формата из `SpeechSynthesisOutputFormat`. По
умолчанию `Raw24Khz16BitMonoPcm`: сырой PCM уходит в ffmpeg без разбора
контейнера, это самый дешёвый по CPU вариант.

Голоса SaluteSpeech (`SALUTE_VOICE`): `Nec_24000`, `Bys_24000`, `May_24000`,
`Tur_24000`, `Ost_24000`, `Pon_24000`, `Kin_24000`.

## Про TLS-сертификат Сбера

Актуально, только если вы переключились на `TTS_PROVIDER=salute`. Сервер
авторизации `ngw.devices.sberbank.ru` использует сертификат, выпущенный НУЦ
Минцифры. Если корневой сертификат не установлен в систему, вы получите ошибку
проверки сертификата. Варианты:

- **Правильный:** установить корневой сертификат Минцифры
  (https://www.gosuslugi.ru/crt) в доверенные корневые ЦС.
- **Быстрый (менее безопасный):** в `.env` поставить `VERIFY_SSL=false`.

Azure этого не требует — его сертификаты в системном бандле.

## Файлы проекта

- `bot.py` — логика Discord-бота, очередь воспроизведения, выбор провайдера.
- `azure_tts.py` — клиент Azure Speech (SDK) и пул ключей.
- `salute_tts.py` — клиент SaluteSpeech (OAuth + синтез) и пул ключей.
- `tts_base.py` — общий интерфейс и класс ошибок для обоих провайдеров.
- `usage.py` — локальный счётчик израсходованных символов.
- `allowed_users.json` — список озвучиваемых игроков (ID/ники),
  создаётся из `allowed_users.example.json` и не коммитится.
- `.env` — секреты и настройки (создаётся из `.env.example`).
